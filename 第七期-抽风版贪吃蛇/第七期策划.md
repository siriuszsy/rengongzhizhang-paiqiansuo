# 第七期策划：抽风版贪吃蛇

## 标题

主标题：

`我不改代码，让 AI 做了个抽风版贪吃蛇，结果第 2 局开始报复我`

备选：

- `我让 AI 一次性做了个抽风版贪吃蛇，不准改代码，结果真能玩？`
- `派遣所给 AI 派了个硬活：做个会发疯的贪吃蛇`

## 一句话 hook

`今天不给 AI 派图活了，直接派个游戏活：不准手改代码，让它做个会突然发疯的贪吃蛇，我现场试玩。`

## 这期要解决什么问题

- 让观众理解 `派遣所验货` 这个栏目是干什么的
- 验证 `vibe coding + 现场试玩 + 翻车` 这类内容有没有节目感
- 用明确规则提升可信度，不做纯炫技

## 最适合的发布形式

首发形式：

- `30-50 秒竖屏短视频`

不要先做成长视频。

这期最优长度不是 70 秒以上，而是：

- 推荐长度：`40-50 秒`
- 理想长度：`45 秒左右`

原因：

- 规则简单，适合快节奏讲清楚
- 真正好看的部分是 `限制 + 试玩 + 翻车`
- 太长会拖垮完播

## 视频结构

核心结构：

`任务 -> 规则 -> 生成 -> 试玩 -> 翻车 -> verdict`

### 逐秒时间线

#### 0-3 秒：直接抛任务

台词方向：

`今天给 AI 派个硬活，不准我改代码，让它直接做个抽风版贪吃蛇。`

画面：

- 一闪而过的游戏成品
- 或者直接上最离谱的翻车画面

#### 3-6 秒：规则页

字幕只保留 3 条：

- `最多 3 次 prompt`
- `不手改代码`
- `最后真人实玩`

画面：

- 纯字幕卡
- 或 IDE / 聊天界面快速切换

#### 6-14 秒：派活过程

台词方向：

`我给它的要求很简单：普通贪吃蛇 + 毒苹果 + 随机发疯事件。`

画面：

- prompt 关键句
- 代码生成片段
- 不要长时间录 IDE

保留重点：

- 它开始看起来像要成了

#### 14-22 秒：第一次跑起来

台词方向：

`它居然真的跑起来了。`

画面：

- 游戏启动成功
- 第一局刚开始的正常表现

这一段的作用是先给观众一个“好像真的行”的感觉。

#### 22-35 秒：真人试玩

这是整条视频最重要的一段。

必须保留：

- 真实操作
- 吃到食物
- 毒苹果或随机事件触发
- 明显失控的一瞬间

台词方向：

- `前面还挺正常`
- `等一下，它开始发疯了`
- `这反向控制是什么东西`

#### 35-42 秒：翻车或离谱点

把最有戏的 bug 留在这里。

优先级：

1. 反向控制把你害死
2. 突然加速
3. 墙体逻辑抽风
4. 明显能玩但明显在整你

这一段要让观众产生：

`这东西居然真能玩，但也真的很欠。`

#### 42-50 秒：最终 verdict

台词方向：

- `能玩，但 AI 明显想害我。`
- `这东西算交差了，但绝对不算安分。`

最后一句一定留互动：

`下一次你们想让派遣所逼 AI 现做什么？`

## 内容形式建议

### 最优拍法

- `录屏为主`
- `配音或现场反应音`
- `不强制真人出镜`

建议形式：

- 70% 游戏画面和生成过程
- 20% 规则卡 / verdict 卡
- 10% 你的反应音或鼠标操作感

不建议：

- 大段讲技术原理
- 长时间拍 IDE
- 太多 prompt 细节
- 教学化口吻

## 游戏本体建议

不要把玩法做得太复杂。

第一版只保留：

1. `普通食物`
2. `毒苹果`
3. `随机事件`

随机事件建议只上 2-3 个：

- 反向控制 `3 秒`
- 突然加速
- 边缘临时变墙

不要再塞更多机制。

原因：

- 第一条最重要的是 `看得懂`
- 不是拼功能，而是拼节目效果

## 拍摄流程时间线

### 1. 制作阶段

建议控制在：

- `60-90 分钟` 内做完第一版

如果 90 分钟还没有能玩的结果，就不要硬磨，直接把失败也拍进去。

### 2. 录制阶段

建议控制在：

- `15-20 分钟`

要录的素材：

- prompt 输入
- 首次生成
- 启动成功或失败
- 试玩 2-3 局
- 最离谱的 bug 一次

### 3. 剪辑阶段

建议控制在：

- `30-45 分钟`

剪辑优先级：

1. 先保住节奏
2. 再保住笑点
3. 最后再补规则字幕

## 封面建议

封面文案建议只放一句：

`AI做了个会发疯的贪吃蛇`

备选：

- `不改代码，AI现场做贪吃蛇`
- `第2局它就开始报复我`

封面画面：

- 游戏界面最混乱、最离谱的那一帧
- 不要用代码界面当封面

## 正文方向

正文不要写成教程。

建议语气：

```text
这次不给 AI 派图活了，直接派个游戏活。

规则很简单：
不改代码，让它一次性做个会突然发疯的贪吃蛇，我现场试玩。

本来以为最多是做丑一点，结果第 2 局开始它像在故意整我。

你们还想看派遣所逼 AI 现做什么？
```

## 首评建议

`下一次你们想让派遣所逼 AI 现做什么，评论区直接派活。`

## 这期成功的判断标准

不是看代码写得多漂亮。

而是看这 4 个结果：

1. 用户能不能在 3 秒内看懂题目
2. 试玩过程有没有至少 1 个明显笑点
3. 评论区会不会开始给 `派遣所` 派新活
4. 用户会不会意识到：这个号不只会发图

## 这期最怕的 3 个问题

1. `太像教程`

会把内容做硬，失去节目感。

2. `太像长录屏`

用户会走，完播会差。

3. `游戏太复杂`

观众看不懂，AI 也更容易翻车翻得没重点。

## 最终建议

这期不要追求“做出一个完美游戏”。

正确目标是：

`做出一个能玩、会翻车、而且翻车翻得很好笑的游戏。`
