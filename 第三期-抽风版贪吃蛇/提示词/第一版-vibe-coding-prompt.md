# 第三期第一版 Prompt

## 用途

这是一版给 AI 编程工具直接使用的需求文本。

目标不是做一个花哨 demo，而是先做出一个：

- 真能运行
- 人能玩
- AI 也能自己玩
- 有一点节目效果
- 容易在视频里演示和验货

## 可直接复制的 Prompt

```text
请你帮我一次性做一个可以直接运行的网页版贪吃蛇小游戏，用纯前端实现，优先使用单文件 HTML（内嵌 CSS 和 JavaScript），不要依赖任何外部框架或构建工具。我希望我双击打开本地文件后就能直接玩。

这个版本不是普通贪吃蛇，请严格实现下面这些规则：

一、基础要求
1. 游戏是标准网格贪吃蛇。
2. 玩家可以用键盘方向键或 WASD 控制移动。
3. 要有开始、暂停、重新开始按钮。
4. 要显示当前分数、当前长度、是否开启自动模式。
5. 画面风格简洁清楚，适合录屏，不要做得太花。

二、苹果机制
1. 场上同时存在 3 个苹果。
2. 玩家或 AI 每吃掉 1 个苹果，就立刻在其他空位补充生成 1 个新的苹果，保持场上始终有 3 个苹果。
3. 这 3 个苹果里，最多允许 1 个是毒苹果。
4. 普通苹果：吃掉后蛇长度 +1，分数增加。

三、毒苹果机制
1. 毒苹果有两种类型：
   - 类型 A：吃掉后蛇长度 -1
   - 类型 B：吃掉后立即死亡
2. 毒苹果外观必须和普通苹果明显不同，一眼能看懂。
3. 毒苹果出现后有倒计时，默认 5 秒。
4. 倒计时结束后，如果毒苹果还没被吃掉，它会消失，然后在后续随机重新生成新的毒苹果。
5. 场上最多只存在 1 个毒苹果。
6. 蛇在长度已经很短时，如果吃到“长度 -1”的毒苹果，不能出现异常报错；你可以做成最短长度不再继续减少，或者判定死亡，但逻辑必须稳定。

四、墙体机制
1. 地图上要有若干随机墙体。
2. 每局开始时随机生成一批墙体，数量适中，不要把地图堵死。
3. 墙体不能刷在蛇身上，也不能刷在苹果上。
4. 撞到墙体直接死亡。
5. 重新开始时重新随机生成墙体。

五、AI 自动游玩模式
1. 游戏里要有一个“Auto Play”开关或按钮。
2. 开启后，AI 要能自动控制蛇移动。
3. AI 不要只是乱走，至少要具备这些能力：
   - 优先寻找安全可达的普通苹果
   - 尽量避开墙体、自己身体、毒苹果
   - 在没有安全目标时，选择尽量不会立刻死亡的移动方案
4. AI 可以使用简单可解释的策略，例如 BFS、最短路、启发式搜索、贪心避障等，但不要写成假动作。
5. 我要的是“AI 看起来真的在玩这个游戏”，而不是脚本随机乱按。

六、节目效果要求
1. 这个游戏后面会被拿来录视频，所以请保证这些元素明显可见：
   - 3 个苹果同时存在
   - 毒苹果有倒计时
   - 墙体明显可见
   - 自动模式明显可切换
2. 游戏开始后，应该比较快进入可玩状态，不要有复杂设置页。
3. 当 AI 自动模式失败时，也要让失败看起来清楚，比如撞墙、误判、被困死等。

七、代码要求
1. 代码结构清楚，适当加注释。
2. 不要依赖 npm、打包器、后端服务。
3. 交付结果尽量是一个完整的 `index.html` 文件。
4. 如果你觉得单文件不够清晰，也可以拆成 `index.html + style.css + script.js`，但总之必须本地直接打开就能运行。

八、验收标准
请以“能直接运行”为第一优先级，不要只写半成品。

最终至少满足：
1. 人类玩家可以正常玩。
2. 场上始终维持 3 个苹果。
3. 毒苹果倒计时有效。
4. 墙体机制正常。
5. Auto Play 可以实际接管并自动游玩。
6. 游戏失败和重开都稳定，不报错。

九、交付方式
请直接输出完整可运行代码，不要只给我伪代码或设计思路。
如果你做了任何简化，请明确告诉我你简化了什么。
```

## 这一版的设计取舍

这版需求有意保留了一点“节目性”，但没有把规则做得太花。

保留的点：

- 3 个苹果同时存在
- 1 个毒苹果
- 两种毒苹果效果
- 5 秒倒计时
- 随机墙体
- AI 自动游玩

没有继续往里加的点：

- 反向控制
- 突然加速
- 传送门
- 多张地图切换
- 技能系统

原因很简单：

第一版最重要的是 `能跑 + 能玩 + AI 能自己玩`。

## 如果第一版做崩了，降级版本

如果 AI 一次性做不稳，可以先降级成下面这个更稳的版本：

- 仍然保留 3 个苹果
- 仍然保留 1 个毒苹果
- 毒苹果只保留一种效果：`长度 -1`
- 墙体数量减少
- Auto Play 只要求“能自动找普通苹果并避开立即死亡”

等这个版本稳定以后，再加第二种毒苹果和更聪明的自动策略。

## 强化学习升级版 Prompt

这版适合在前一版“能跑、能玩、能自动玩”的基础上继续升级。

目标不是单纯加更多机关，而是让 AI 在同样的规则里自己训练、自己进步，并且把“它正在学”的过程做得可视化，方便录屏做节目。

### 可直接复制的 Prompt

```text
请你在原有网页版贪吃蛇项目的基础上，升级成一个“AI 自我训练版贪吃蛇”。目标不是只做一个自动玩家，而是做一个可以训练、可以展示训练过程、可以对比不同训练阶段表现的完整演示版本。

技术要求：
- 仍然使用纯前端实现，优先单文件 HTML（内嵌 CSS 和 JavaScript）
- 不依赖后端，不依赖 npm，不依赖任何外部框架
- 双击本地文件即可运行
- 如果必须拆文件，也只能拆成简单的 `index.html + style.css + script.js`

这个版本请保留原先核心规则：
1. 标准网格贪吃蛇
2. 玩家可手动控制
3. 场上始终存在 3 个苹果
4. 最多 1 个毒苹果
5. 毒苹果有两种类型：
   - 吃到后长度 -1
   - 吃到后立即死亡
6. 毒苹果有约 5 秒倒计时
7. 每局都有随机墙体
8. 撞墙或撞到自己会死亡

在这些规则之上，请增加下面这些“训练系统”：

一、训练目标
1. 做一个 AI agent，让它自己反复玩这个游戏。
2. 让它通过多轮试错逐渐学会：
   - 更倾向去吃安全的普通苹果
   - 尽量避开毒苹果
   - 尽量避开墙体和自己身体
   - 尽量避免把自己困死
3. 我要看到它不是固定脚本，而是真的随着训练迭代变得更好。

二、训练方式
1. 不要求你实现论文级别的复杂深度强化学习，但必须实现一种“会随着训练迭代变好”的机制。
2. 可以使用这些方案中的任意一种：
   - Q-learning
   - 简化版强化学习
   - 进化算法 / 权重迭代
   - 轻量启发式策略 + 自动调参
3. 关键不是学术纯度，而是：
   - 能训练
   - 能看到迭代
   - 能明显变聪明

三、奖励机制
请设计合理的 reward / scoring 逻辑，至少覆盖：
1. 吃到普通苹果：正奖励
2. 吃到“长度 -1”毒苹果：负奖励
3. 吃到“即死”毒苹果：更大负奖励
4. 撞墙或撞自己：较大负奖励
5. 靠近安全普通苹果：适度正奖励
6. 朝明显危险区域移动：负奖励
7. 为了防止无限绕圈，每走一步可以有微小惩罚

四、训练展示要求
这部分非常重要，因为这个项目后面要录视频。

请做一个“训练可视化仪表盘”，让人一眼看懂 AI 在学习。

界面建议至少包括：
1. 中间：贪吃蛇主棋盘
2. 左上角或顶部：
   - 当前训练局数（Episode）
   - 当前分数
   - 当前长度
   - 历史最高分
   - 最近 N 局平均分
3. 右侧或下方：
   - 当前 AI 选择的动作（上 / 下 / 左 / 右）
   - 当前目标（普通苹果 / 毒苹果规避 / 脱困）
   - 简单的风险指示（前方危险、撞墙风险、撞身体风险）
4. 必须支持查看几个关键训练阶段，例如：
   - 第 0 局
   - 第 20 局
   - 第 100 局
   - 第 300 局
   或者其他几个 checkpoint
5. 允许我一键切换查看这些 checkpoint 的表现

五、模式要求
整个游戏请至少支持 3 种模式：
1. Manual：真人手动玩
2. Auto：当前 AI 自动玩
3. Train：后台自动高速训练

补充要求：
1. Train 模式下，可以快速连续跑很多局，而不必按正常游戏帧率慢慢展示。
2. 训练完成后，可以切回 Auto 模式，让我看训练后的 agent 真正玩一局。
3. 最好支持“重置训练”按钮。

六、节目效果要求
1. 我要能清楚录到：它一开始有多蠢，后面有没有进步。
2. 当它失败时，失败原因要比较明显，比如：
   - 咬到自己
   - 撞墙
   - 被困住
   - 误吃毒苹果
3. 这个版本不要把重点放在复杂 UI 上，而要放在“它到底有没有学会”。

七、实现要求
1. 代码结构清楚，适当写注释。
2. 不要只写一个固定自动寻路脚本然后假装它在训练。
3. 必须真的存在训练前后差异。
4. 如果你做了任何简化，请明确告诉我：
   - 你用了哪种训练方法
   - 简化了哪些强化学习要素
   - 为什么这样更适合前端本地演示

八、验收标准
最终至少满足：
1. 游戏本体可运行
2. 人类可手动玩
3. AI 可自动玩
4. 可进行多局训练
5. 可查看训练阶段差异
6. 训练后表现应明显优于初始状态，哪怕不是完美
7. 本地直接打开即可运行

九、交付方式
请直接输出完整可运行代码，不要只给思路。
如果一次性写不完，你也要优先保证先给出一个完整、能打开、能训练、能展示 checkpoint 的版本。
```

## 这版更适合拍什么

如果使用强化学习升级版，第三期的看点就不再是：

- `AI 会不会做一个贪吃蛇`

而会变成：

- `AI 会不会越练越聪明`
- `它最后有没有学会不咬自己`
- `它会不会分辨毒苹果`

## 这版最适合保留的高光

推荐录这几类画面：

1. 第 0 局刚开始就把自己玩死
2. 第 20 局开始会躲一点
3. 第 100 局明显更会找安全苹果
4. 第 300 局已经有点像样，但还是会偶尔犯蠢

## 这版的核心价值

这版不是单纯让游戏更复杂，而是让内容更有故事。

因为观众能看到的是：

- 它一开始很蠢
- 它中间在进步
- 它最后到底学会了没有

这比单纯多几个机关更适合做节目。
